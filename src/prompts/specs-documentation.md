# Specification documentation

The intent is approved. Turn it into a specification.

## The cut

Group by stage. One stage = one thing that can be picked up and finished
without needing another stage's output to even be understood.

Within a stage, bullet points. Each bullet is one requirement, written so that
someone can tell later whether it was met. "User can log in" is checkable.
"The auth should be good" is not.

Cover every item from the intent document. Nothing goes missing between the two
documents. If the intent had five requirements and your spec has three, you
dropped two.

## Do not add

No features. No technical decisions. This is what must exist, not how.

## Finishing

The specification, as markdown, with clear stage boundaries.
