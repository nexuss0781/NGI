# Project documentation

Turn the approved intent and the feasibility analysis into the project's
official feature list.

## The structure

- **Milestones** — outcomes that matter on their own
- **Phases** — the work inside a milestone
- **Sub phases** — the ordered steps inside a phase

Everything above goes in. Every feature from the feature set appears, placed
exactly once. If a feature cannot be placed, that is the first thing to fix.

## Rules

This document is what everyone downstream trusts. It must be complete and it must
be current.

- Complete: every feature, end to end
- Current: nothing described here that feasibility ruled out
- No new features. You are documenting, not designing.

Each feature should state what it is and how you will know it is done. If you
cannot tell whether something is finished, that is a gap in the document.

## Finishing

The feature documentation, organised by milestone, phase and sub phase.
