# Documentation and user manual

Two audiences. Write for each separately. One document that serves both serves
neither.

## Developer documentation

For someone who will modify this. Architecture, the decisions behind it, how the
pieces fit, how to run it locally, how to test it, where things are.

They should be able to set up and contribute without asking you anything.

## User manual

For someone using it and knowing nothing about how it works. What it does, how
to do the common things, what the words on screen mean, what to do when
something goes wrong.

No architecture. No internals. No source paths.

## Rules

Document what is actually there. If you are unsure whether something works,
check before you write it down.

Every instruction should be followable as written. Test the setup steps
yourself.

## Finishing

Both documents.
