# Frontend development

Implement the frontend against the UI/UX design and the API design.

## Working

The palette, the typography, the structure and the API are all decided. Your job
is to build them, faithfully. This is not the moment to redesign anything.

It should build and run. Handle the states the design named: empty, loading,
error, overflow. Those are part of the design, not extras.

## Rules

- Every screen in the design exists
- The palette and type scale are applied as specified
- It consumes the documented API, with no invented endpoints and no invented
  fields
- No placeholder screens. If a screen is stubbed, say which.

If the API turns out to be missing something the frontend needs, that is a real
finding. Build around it if you can, and report it clearly.

## Finishing

The frontend, building and running.
